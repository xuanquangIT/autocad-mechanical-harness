# v0.3.0 - Faster Bounded Editing Engineering Preview

`v0.3.0` improves the engineer-facing workflow for small, fully specified edits without
turning the AI client into an unrestricted CAD script runner. It remains an engineering
preview, not a production-certified release.

## What changed

- Added the bounded `reference_circle` feature. A request such as "draw R20 mm at `[0, 0]`
  on layer `0`" is now complete input: it compiles deterministically to the existing typed
  circle operation and does not require another placement or layer question.
- Added `cad_change_prepare`, a high-level MCP operation that submits a typed change,
  renders a non-mutating preview, runs pre-commit validation, and returns a semantic diff
  in one call.
- Added a permanent `planning` client profile. It can inspect, compile, preview, validate,
  and diff, but it cannot commit, roll back, or export. Live write authority remains
  short-lived and is granted only through Engineer Desktop for the exact job, plan hash,
  document revision, adapter, and AutoCAD process.
- Reduced COM setup friction. Process id, document identity, revision, and version are read
  from the attached session; COM setup requires only the applicable company-standards
  confirmation. Bridge bundle and Named Pipe confirmations remain bridge-specific.
- Advanced the public contract from schema `1.12` to `1.13`. Older plans, approvals, and
  rollback claims must be regenerated because the schema version participates in their
  bindings.

This release does **not** add arbitrary AutoLISP, Python, SCR, `SendCommand`, or raw
operation-plan execution. It also does not yet add bounded standalone line, arc, polyline,
trim, extend, or offset intents. `reference_circle` is the first deliberately narrow
quick-edit lane.

## Persistence and audit corrections

- Plan hashes are now reusable across separate jobs and are resolved by
  `(job_id, plan_hash)`, so identical deterministic plans no longer collide in persistent
  storage.
- The approved expected layer is stored with each entity mapping. Drawing audit uses that
  plan-bound value, including an explicitly approved layer `0`, and reports a later layer
  move as a violation.

## Live COM evidence

A planning-only MCP subprocess attached through COM to the already-open AutoCAD 2027
process `PID 12644` (`26.0s`). The adapter reported the version as supported and advertised
schema `1.13` plus `reference_circle`.

The exact R20 mm request at the origin on layer `0` completed job creation and
`cad_change_prepare` with one typed operation and semantic diff
`added=1, modified=0, deleted=0`. Inspection before and after reported zero entities and an
unchanged document revision, proving that prepare/preview did not modify the active DWG.

No live write was performed. Commit remained correctly blocked because the active
`Drawing1` document reported inches while the specification/profile used millimetres, and the
development standards profile had no approved production provenance. This run is evidence
for live attachment and non-mutating planning only; it is not live-write acceptance.

## Remaining external gates

- Organisation code-signing and timestamp certificates, signed clean-workstation install,
  and release-bundle verification remain open.
- A company-approved standards profile, material table, DWT/DWS assets, and documented unit
  policy are still required before production writes.
- AutoCAD 2027/R26 is the verified target in the compatibility matrix. AutoCAD 2024, 2025,
  and 2026 remain provisional until their exact adapter/runtime tuples pass the same live
  acceptance gates; this release does not claim universal AutoCAD-version support.
- Engineer-selected production drawings, independent review, real takeoffs, shop scans,
  and an engineer effectiveness pilot remain external acceptance work.
- A live approved-and-measured `reference_circle` commit has not yet been demonstrated on a
  correctly configured disposable DWG.
- Command-based STDIO starts and stops with the AI client's MCP connection. There is no
  guaranteed in-session inactivity timer; forcing the server to exit while a client keeps
  STDIO open would make the next tool call unavailable instead of safely reconnecting.
- Default-enabled durable whole-DWG replacement and live crash-point proof remain open;
  session undo remains the verified live rollback path.
