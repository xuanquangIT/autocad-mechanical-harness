# Governance

AutoCAD Mechanical Harness uses a maintainer-led, evidence-driven governance model.

## Maintainer

The current lead maintainer is [@xuanquangIT](https://github.com/xuanquangIT). The maintainer
is responsible for releases, repository settings, security coordination, architecture
decisions, and final merge decisions.

## Decision making

Routine changes are decided through issue and pull request review. Decisions favor:

1. Safety invariants and protection of customer drawing data
2. Deterministic, measurable behavior
3. Backward-compatible public contracts
4. Reproducible test and acceptance evidence
5. Simplicity and maintainability

Large public contract, dependency, licensing, or architecture changes require a public design
discussion and an Architecture Decision Record before implementation.

When consensus is not reached, the lead maintainer makes the decision and records the
rationale. Security-sensitive details may be discussed privately until coordinated disclosure.

## Becoming a maintainer

Contributors may be invited as maintainers after a sustained record of high-quality reviews or
contributions, respectful community participation, sound engineering judgment, and careful
handling of safety and disclosure boundaries. Write access is never granted solely for a single
large contribution.

## Changes to governance

Governance changes use the same public pull request process. The project may move to a broader
maintainer council as the contributor base grows.
